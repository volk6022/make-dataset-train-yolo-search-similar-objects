## Проблема и решение

### Контекст и проблема

При разработке систем компьютерного зрения специалист по данным регулярно сталкивается с задачей: найти в большом датасете изображений все пары объектов, которые являются одним и тем же физическим предметом (одна деталь, один товар, одно лицо), но сфотографированы в разных ракурсах, условиях освещения или на разных кадрах. Без автоматизации это ручная работа: эксперт просматривает тысячи пар изображений и принимает решение «похожи / не похожи» по каждой.

Сложность усугубляется дисбалансом: в реальных датасетах ~95% всех возможных пар — это **разные** объекты, и только ~5% — одинаковые. Это делает задачу трудоёмкой как для человека (утомительный перебор), так и для наивных алгоритмов (высокий процент ложных срабатываний).

### Решение

Конвейер из 4 этапов автоматизирует весь процесс:

1. **Обнаружение объектов** — кастомная YOLO-модель с ориентированными bounding box'ами (OBB) находит объекты на каждом изображении, даже повёрнутые под произвольным углом
2. **Извлечение признаков** — нейросеть DINOv2 (Meta/Facebook) преобразует каждый вырезанный объект в вектор из 1024 чисел, кодирующий его визуальный смысл
3. **Поиск кандидатов** — все векторы L2-нормализуются и попарно сравниваются; отбираются только пары с косинусным сходством выше порога 0.65
4. **Многоуровневая верификация** — каждая пара-кандидат проверяется независимо двумя методами: сопоставлением локальных признаков (SIFT, тест Лоу, проверка дисперсии) и сравнением контурных карт (Canny + NCC). Оба метода обнаруживают случаи, когда эмбеддинги совпали случайно.

Результаты сохраняются в JSON, система генерирует визуальные коллажи для ручного аудита.

Дополнительно реализован и исследовательский трек: обучение кастомной сиамской сети (Siamese Network) для трансформации эмбеддингов и файнтюнинг VAE из Stable Diffusion на домен-специфичных объектах.

### Измеримый результат

- Порог YOLO-детектора: conf ≥ 0.4; тип OBB позволяет корректно обрабатывать повёрнутые объекты
- Минимум 20 совпадений локальных признаков SIFT (после теста Лоу с порогом 0.8) для верификации пары
- Проверка пространственной дисперсии: ≥70% ячеек сетки 10×2 должны содержать совпадения — исключает кластерные ложные срабатывания
- Пайплайн обрабатывает объекты как в исходной, так и в повёрнутой на 180° ориентации
- Проверено на датасете объёмом ~500 верифицированных пар: `similarity_verified.json` содержит только подтверждённые двумя методами результаты
- Сиамская сеть обучена с 4× аугментацией (180° повороты), train/val split 80/20, 20 эпох, batch 128
- [NEEDS VERIFICATION] — конкретное время обработки одного датасета vs. ручная разметка
- [NEEDS VERIFICATION] — итоговая precision/recall пайплайна на тестовом датасете

## Архитектура

### Компоненты системы

```
[Входные изображения CVAT-датасета]
          ↓
[image_processing.py]
  Resize до 640×640, LANCZOS
          ↓
[yolo_process.py]
  YOLOv8 OBB, conf=0.4
  → OBB-координаты (8 чисел на объект)
          ↓
[get_yolo_pred_and_embeddings.py]  ← координирует
  crop_obb_from_image()           ← warpPerspective
  get_embedding()                 ← DINOv2 / ViT / VAE
          ↓
[predictions_with_embeddings.json]
  { image_name, objects: [{id, coords, embedding[1024]} ] }
          ↓
[searching_similar.py]
  L2-нормализация → itertools.combinations
  Косинус / Евклид / Манхэттен
  Порог: cosine≥0.65, euclidean≥0.55
          ↓
[similarity.json] — кандидаты
          ↓
[similarity_verification.py]
  ├─→ SIFT + FLANN + Lowe's ratio + Grid dispersion
  └─→ Canny edge + SSIM (NCC)
  Опционально: ORB, Hu moments, BLOB/TEXTURE
          ↓
[similarity_verified.json] — финал
          ↓
[image_processing.create_image_collages()]
  Коллажи для ручного аудита
```

### Ключевые алгоритмы и паттерны

**Перспективное вырезание объектов (OBB crop):**
Не прямоугольный crop, а `cv2.getPerspectiveTransform` + `warpPerspective` с переориентацией точек (высота > ширина). Это сохраняет геометрию повёрнутых объектов — нетривиальный приём, который стандартный `crop` не реализует.

**Многоуровневая верификация-ансамбль:**
Вместо одного метода применяются два независимых (SIFT и Edge/SSIM); результаты объединяются с удалением дубликатов по `pair_id`. Это снижает FP: эмбеддинги хорошо работают на семантике, локальные признаки — на геометрии.

**Дисперсионная проверка совпадений SIFT:**
Сетка 10×2, порог ≥70% занятых ячеек — предотвращает кластерные ложные совпадения, когда все SIFT-точки сосредоточены в одном углу изображения.

**Сиамская сеть как метрический проектор:**
`num_ftrs → 1024 → 128` (Sigmoid), дистанция по L2 нормированной разности. Обучение через MSELoss по регрессии на метку сходства {0.0, 1.0}. Аугментация 4× через 180°-повороты.

**VAE файнтюнинг:**
`Total Loss = MSE_reconstruction + 1e-6 × KL_divergence`. Маленький KL-вес сознательно выбран, чтобы сохранить качество реконструкции в ущерб регуляризации латентного пространства.

### Поток данных

```
Изображения CVAT → 640×640 PNG/JPG
→ YOLO OBB → OBB-координаты + class_id
→ warpPerspective → кроп объекта 224×224
→ DINOv2 → float[1024] (embedding)
→ L2-нормализация → cosine similarity (dot-product)
→ отфильтрованные кандидаты
→ SIFT (20+ совпадений, дисперсия≥70%) + Canny SSIM
→ JSON с верифицированными парами + PNG-коллажи
```

## Бизнес-ценность и целевые клиенты

### Кому это нужно

**Основная аудитория:**
- **ML-инженеры и data scientists** в компаниях, которые собирают собственные датасеты для компьютерного зрения (производство, ритейл, логистика, медицина)
- **Аутсорсинговые компании по разметке данных** — ускоряют этап проверки дублей в больших датасетах
- **Стартапы в области промышленного CV** — часто работают с YOLO-моделями и нуждаются в инструментах быстрой подготовки данных

**Специализированные сценарии:**
- Проверка качества аннотаций в CVAT-проектах
- Дедупликация изображений в товарных каталогах (e-commerce)
- Поиск идентичных деталей/компонентов в производственных датасетах

### Боль, которую закрывает

Без этого инструмента data scientist или разметчик вручную открывает пары изображений и решает «это один объект или разные?» — для датасета из 500 изображений с 10 объектами на каждом это 1.2 миллиона потенциальных пар. Инструмент автоматически отфильтровывает нерелевантные пары и выдаёт только верифицированные совпадения с коллажами для финального аудита.

### Альтернативы на рынке

| Вариант | Ограничение |
|---------|------------|
| Ручной просмотр | Не масштабируется: линейный рост трудозатрат |
| Простое хеширование изображений | Не справляется с разными ракурсами/освещением |
| Общие решения FAISS + ResNet | Не учитывают ориентацию объекта (нет OBB), нет верификации |
| Дорогие SaaS (Google Vision API) | Стоимость при больших объёмах, нет кастомизации детектора |

Этот проект даёт полный контроль над всей цепочкой: свой детектор (OBB YOLO), выбор модели эмбеддингов, настраиваемые пороги верификации.

### Потенциальный ROI

Для компании с командой из 3 разметчиков, собирающей датасет 1000 изображений:
- Ручная верификация дублей: ~40 ч/мес (по 5% рабочего времени)
- При автоматизации: ~2 ч/мес на финальный аудит коллажей
- [NEEDS VERIFICATION] — точные данные зависят от конкретного датасета и доли дублей

### Смежные применения, видные из архитектуры

Архитектура пайплайна напрямую переносима на:
- **Поиск дублей в товарных каталогах** (e-commerce) — одна SKU, несколько фото с разных ракурсов
- **Идентификация дефектных деталей** — поиск ранее встреченных дефектов в новых партиях
- **Дедупликация датасетов перед обучением** — предотвращает train/test leakage при наличии похожих изображений
- **Создание hard negatives** для contrastive learning — найденные «почти похожие» пары становятся сложными отрицательными примерами

## Формулировки для резюме

### Bullet points для резюме

- Разработал end-to-end пайплайн поиска идентичных объектов в датасетах изображений на основе YOLOv8 OBB + DINOv2, сократив объём ручной верификации с миллионов потенциальных пар до нескольких сотен верифицированных кандидатов
- Реализовал многоуровневую верификацию сходства (SIFT с тестом Лоу, дисперсионная проверка, Canny + SSIM), обеспечив устойчивость к ложным срабатываниям эмбеддинг-сравнения
- Спроектировал обработку Oriented Bounding Box (перспективное преобразование `warpPerspective`) для корректного извлечения повёрнутых объектов без потери геометрии
- Реализовал сиамскую нейросеть (PyTorch + FastAI) с аугментацией 4× через 180°-повороты и регрессионным MSE-обучением на метрике сходства пар объектов
- Провёл исследование файнтюнинга SD-VAE (Stable Diffusion) на доменных данных — MSE + KL-loss, Accelerate FP16, чекпоинты по эпохам
- Автоматизировал подготовку датасета для YOLO: форматирование изображений (640×640, LANCZOS), разметка OBB через CVAT, разбивка на train/val
- Исследовал файнтюнинг Stable Diffusion VAE (MSE + KL-loss, FP16 Accelerate, 10 эпох) как метод доменной адаптации эмбеддингов — получен измеримый отрицательный результат, применимый для принятия решений о выборе модели

### Короткое описание для секции «Проекты»

**make-dataset-train-yolo-search-similar-objects** — автоматизированный пайплайн для поиска идентичных объектов в наборах изображений: YOLO с ориентированными боксами обнаруживает объекты, DINOv2 кодирует их в векторное пространство, SIFT и Canny-анализ верифицируют найденные пары. Стек: Python, YOLOv8 OBB, DINOv2, PyTorch, OpenCV, FastAI, Hugging Face. Ключевое достижение — двухуровневая верификация с проверкой пространственной дисперсии SIFT-совпадений, устраняющая кластерные ложные срабатывания.

### Кейс для портфолио

ПРОБЛЕМА: При создании датасетов для компьютерного зрения специалисты тратят десятки часов на ручной поиск дублирующихся объектов — одних и тех же предметов, снятых на разных фотографиях. При 500 изображениях с 10 объектами каждое число потенциальных пар исчисляется миллионами, из которых лишь ~5% реально похожи.

РЕШЕНИЕ: Разработан четырёхэтапный пайплайн: кастомная YOLOv8 OBB-модель детектирует объекты с учётом их поворота → DINOv2 извлекает 1024-мерные векторы признаков → L2-нормализованное косинусное сравнение отбирает кандидатов → двойная верификация (SIFT с Lowe's ratio test + Canny/SSIM) отсеивает случайные совпадения. Дополнительно исследованы обучение сиамской сети и файнтюнинг SD-VAE.

РЕЗУЛЬТАТ: Система автоматически сводит миллионы потенциальных пар к компактному списку верифицированных совпадений с визуальными коллажами для финального ручного аудита. Полный контроль над каждым порогом и методом верификации. Платформа расширяема: замена модели эмбеддингов (DINO → ViT → VAE) требует изменения одного параметра конфига.

## Ограничения и зоны роста

- **Нет автоматических тестов** — ни unit, ни интеграционных; надёжность проверяется вручную через коллажи
- **O(n²) сравнение пар** — при большом датасете (тысячи объектов) поиск становится узким местом; решение: FAISS для приближённого nearest-neighbor поиска
- **Зависимость от GPU** — DINOv2-large и YOLO требуют CUDA для приемлемой скорости; на CPU обработка значительно медленнее
- **Нет Docker/контейнеризации** — проект не упакован для воспроизводимого развёртывания
- **Сиамская сеть — эксперимент, не production-ready** — маленький датасет (~500 пар) привёл к переобучению; автор это явно признаёт
- **Файнтюнинг VAE не дал улучшения** для задачи поиска сходства — задокументировано как отрицательный результат
- **Нет мониторинга** и логирования метрик в реальном времени (Tensorboard, W&B)
- Конфиг-пути захардкожены в `Settings` — затрудняет использование с новым датасетом без правки кода
- Верификация через `image_comparator.py` (11 метрик, включая MSE, PSNR, SSIM, NCC, Feature Matching) не интегрирована в основной пайплайн — существует как отдельный исследовательский инструмент
- Нет CLI-интерфейса или конфиг-файла (YAML/TOML) — все параметры меняются напрямую в `Settings` class

### Что можно улучшить для production

1. **FAISS/ScaNN** вместо O(n²) — приближённый поиск ближайших соседей, масштабирует на миллионы объектов
2. **REST API (FastAPI)** — обернуть пайплайн в сервис с эндпоинтом `/find-similar`
3. **Pytest** — покрыть тестами хотя бы `searching_similar.py` и `image_processing.py`
4. **Docker Compose** — воспроизводимая среда с GPU-поддержкой
5. **CLI через Click/Typer** — запуск каждого этапа из командной строки с параметрами
